## ✅ 一句话总结：

> **动态规划考虑“整体最优”，解决的是“局部最优不一定推出整体最优”的问题；而贪心只考虑“当前最优”，假设每一步的局部最优能够推出全局最优。**因为DP的状态转移公式需要使用上一层的所有状态（符合条件的状态）进行最优状态选择，那么要做好数据结构的边界处理，比如下面的P-DTW算法，建立二维矩阵存储累计距离，那么就需要处理好初始元素的“上一层”状态，故建立`[0,n] x [0,m]`矩阵而不是只建立`[0,n - 1] x [0,m - 1]`矩阵，边界值赋予无穷。但为什么只有 M[0,0]=0
>
> 因为它是 DP 的起点：还没有匹配任何查询元素，也没有匹配任何模板元素，累计代价为零

> ## 为什么必须取三个前驱的最小累计距离？
>
> 这是动态规划的核心。
>
> 假设我们要计算的当前局部距离是：
>
> ​                                                                                   `d(A_3,B_4)=0.1`
>
> 三个前驱状态已经算好的累计距离分别是：
>
> | 前驱状态 | 已有累计距离 | 当前点的局部距离 | 新的累计距离 |
> | -------- | ------------ | ---------------- | ------------ |
> | M[2, 4]  | 0.8          | 0.1              | 0.9          |
> | M[2, 3]  | 0.4          | 0.1              | 0.5          |
> | M[2, 2]  | 0.2          | 0.1              | 0.3          |
>
> 注意，三种方式到达当前点时，当前局部距离都是同一个值 0.1。变化的是到达这里之前，已经累计了多少代价。
>
> 因此：
>
> ​                                              `M[3,4] = 0.1 + min(0.8, 0.4, 0.2) = 0.1 + 0.2 = 0.3`
>
> 算法选择从 M[2, 2] 出发的路径，因为它此前的累计代价最小。
>

>
> 可以把 P-DTW 理解为：`把两段流量波形放在一起，不要求每个时间点严格对应，而是允许波形在时间轴上错位，通过动态规划寻找累计特征差异最小的匹配路径。`
>
> 上图就是这个思想的示意。下面结合两段流量波形，逐步对应到伪代码。
>
> ## 1. 两段波形分别代表什么？
>
> - 波形 A：在线捕获的视频流量特征，转换为一个查询序列。
>- 波形 B：本地指纹库中保存的视频流量特征，转换为一个模板序列。
> 
> 假设横轴是时间，纵轴是某种流量特征，例如单位时间内的数据包数量、流量大小，或者论文定义的其他特征。
> 
>即使是同一段视频，由于网络抖动、采样时间不同、播放速度变化，两条曲线也可能出现时间偏移。
> 
> 例如，A 的一个波峰出现在第 20 个采样点，B 的对应波峰可能出现在第 22 个采样点。
> 
> 如果强制逐点比较，就可能认为两段流量差异很大；P-DTW 则尝试通过调整匹配路径，判断它们的整体形状是否接近。
> 
> ## 2. 对应到伪代码，DP 矩阵在做什么？
> 
> 假设 A 有 n 个采样点，B 有 m 个采样点。
> 
> `M[i,j]=匹配到 A 的第 i 点和 B 的第 j 点时的最小累计代价`
>
> 每次计算：
>
> ![image-20261010194434270](https://pub-64ffffada5d441c18d41525eba7abb52.r2.dev/PicGo/image-20261010194434270.png)
>
>可以把它理解为：
> 
>1. 先计算当前两个采样点的特征差异 `d(Ai,Bj)`。
> 2. 查看上一行三个允许的前驱位置。
>3. 选择累计代价最低的前驱。
> 4. 加上当前点的特征差异，得到 `M[i, j]`。
>
> 这里的三个前驱，分别允许模板序列停留、前进一格或前进两格。它们并不代表三种不同的相似度，而是三种可能的匹配路径。
>
> ## 3. 为什么它可以识别时间错位的波形？
>
> 假设同一段视频的两次流量采样存在轻微时间偏移：
>
> - A 的波峰出现在位置 20。
>- B 的波峰出现在位置 22。
> - A 的波谷出现在位置 32。
>- B 的波谷出现在位置 35。
> 
>逐点比较时，波峰和波谷可能对不上；P-DTW 可以沿着不同的匹配路径，将 A 的波峰与 B 中稍后出现的波峰对应起来，再继续匹配后续特征。
> 
>如果两个波形的形状整体相似，这种时间调整就可能降低累计距离。
> 
>但是要注意，P-DTW 不是直接比较两条曲线的整体轮廓，而是通过离散采样点之间的距离和允许的步进方式，间接评估形状相似性。
> 
>## 4. 回到你之前指出的假匹配问题
> 
>这里正是算法设计中需要重点关注的地方。
> 
>假设 A 的特征序列为：
> 
>`A={1,2,3}`
> 
>B 的特征序列为：
> 
>`B={1,2,4,3}`
> 
>如果允许直接从 `M[2, 2]` 跳到 `M[3, 4]`，那么模板中的特征 `4` 就被跳过了，而且没有受到惩罚。因此，最终距离可能仍然为 0。
> 
>在视频流量识别中，这相当于算法忽略了一个可能有区分价值的流量特征。
> 
>如果不同视频经常出现这样的局部特征重合，就可能发生误识别。
> 
>所以，判断这套算法是否可靠，除了检查 DP 递推式，还需要确认：
> 
>- 是否限制了匹配路径的最大跳跃幅度；
> - 是否对跳过的特征施加惩罚；
>- 是否要求足够高的模板覆盖率；
> - 最终是否结合其他指纹特征进行二次判定。
>
> 最关键的结论：P-DTW 的优势是容忍时间错位，而它的风险是过度容忍跳跃。 对于视频流量指纹识别，好的设计应该既允许同一视频的流量波形发生合理的时间变形，又不能让不同视频仅凭几个相同的采样点就获得零距离。

## 🔍 本质对比

| 维度         | 动态规划（DP）                             | 贪心算法（Greedy）                   |
| ------------ | ------------------------------------------ | ------------------------------------ |
| **核心思想** | 记住历史、对未来做出最优选择               | 每一步都选当前最优，走一步看一步     |
| **最优原则** | 整体最优由多个子问题的**最优组合**构成     | **每一步的最优**直接通向最终最优     |
| **是否回退** | 需要**回退、状态转移**                     | 一旦选择，**不回退、不更改**         |
| **求解方式** | 通常是**递推或递归**（含记忆化）           | 通常是**迭代直接构造解**             |
| **适用问题** | 子问题重叠，**后一步依赖前一步的多种情况** | 问题满足“贪心选择性质”和“最优子结构” |
| **效率**     | 相对较慢（但可优化到 O(n²)、O(n)）         | 通常更快，常为 O(nlogn)、O(n)        |

## 🧠 举例对比

这次我们用一个 6 层数字三角形，比前面的例子多两层，并且把贪心和动态规划都完整演算一遍，最后给出伪代码。

重点不是单纯让贪心走一条“看起来不太好”的路径，而是要明确证明：贪心每一步都选了当前更小的子节点，但最终总代价仍然比 DP 的最优解大。

## 一、贪心算法：逐步走一遍

为了避免相同数字导致的选择歧义，我们使用下面这组经过修正的 6 层数据：

![image-20261010150622392](https://pub-64ffffada5d441c18d41525eba7abb52.r2.dev/PicGo/image-20261010150622392.png)

我们约定：如果两个子节点数值相同，就选左边的节点。

### 每一步的选择

| 层数    | 当前节点 | 左下、右下候选 | 选择 |
| ----- | ---- | ------- | -- |
| 第 1 层 | 1    | 2、3     | 2  |
| 第 2 层 | 2    | 4、9     | 4  |
| 第 3 层 | 4    | 9、10    | 9  |
| 第 4 层 | 9    | 9、10    | 9  |
| 第 5 层 | 9    | 9、10    | 9  |

最终贪心路径为：

​                                                                1→2→4→9→9→9

总路径代价：

​                                                             1 + 2 + 4 + 9 + 9 + 9=34

贪心每一步都严格选择了当前较小的子节点，但它被引导到了左侧的高代价区域。

### 贪心伪代码

假设三角形使用二维数组 `a[i][j]` 保存，第 `i` 行有 `i` 个元素，采用从 1 开始的下标。

```python
Greedy(a, n):
    j = 1
    sum = a[1][1]

    for i = 1 to n - 1:
        left = a[i+1][j]
        right = a[i+1][j+1]

        if left <= right:
            j = j
        else:
            j = j + 1

        sum = sum + a[i+1][j]

    return sum
```

这里 `j` 表示当前节点在本行的位置。若选择左下节点，列号不变；若选择右下节点，列号加 1。

时间复杂度为 O(n)，因为每一层只做一次局部选择。

## 三、动态规划：从底部反向计算

DP 不急着从顶部作决定，而是先计算每个位置从当前位置走到底部的最小路径和。

我们先写出最底层的 DP 值，再逐层向上计算。

​                                                              1 + 3 + 1 + 1 + 1 + 1 = 8

### DP 伪代码

```py
DP(a, n):
    for j = 1 to n:
        dp[n][j] = a[n][j]

    for i = n-1 downto 1:
        for j = 1 to i:
            dp[i][j] = a[i][j]
                      + min(dp[i+1][j],
                            dp[i+1][j+1])

    return dp[1][1]
```

时间复杂度为 O(n²)，因为三角形总共有 n(n+1)/2 个节点；空间复杂度为 O(n²)，如果只保留相邻两层的 DP 值，也可以将空间优化为 O(n)。

## 四、最终对比：两种算法到底差在哪里？

![image-20261010151139431](https://pub-64ffffada5d441c18d41525eba7abb52.r2.dev/PicGo/image-20261010151139431.png)

两者的路径和相差 26。贪心在第一步选择了数字更小的 2，却因此进入了后续代价很高的区域；DP 计算了每个子节点到底部的最小代价，发现从数字 3 出发的完整路径反而更便宜。

这里要建立的关键认识是：

* 贪心： 只比较下一步的局部数值，作出选择后不再反悔。

* 动态规划： 比较下一步对应的最优子问题结果，再决定当前节点的最优值。

这也是为什么做算法题时，不能仅仅因为每一步都能选最小值，就认定贪心一定正确。必须证明局部选择不会损害全局最优性；如果无法证明，就需要考虑 DP 等能够系统比较不同决策的算法。

#### 对于01背包一维优化的一点理解：

![image-20250306163139700](https://github.com/lllxQ000/tuchuangblog-img/blob/main/image-20250306163139700.png?raw=true)

```py
N, V = list(map(int, input().split()))  # 物品件数和总体积
# 这里的（N + 1）其实是创建了下标从0到N的，如果是（N）只会创建0 ~ N-1的
v = [0] * (N + 1)  # 保存每件物品的体积，下标从 1 到 N
w = [0] * (N + 1)  # 保存每件物品的价值，下标从 1 到 N

for i in range(1, N+1):
    v_, w_= list(map(int, input().split()))
    v[i] = v_
    w[i] = w_   # 直接赋值：w[i] = w_
# 二维DP ,f(i,j) = 只从前i件物品中选，体积小于等于j的所有选法中价值的最大值
f = [[0]*(V+1) for i in range(N+1)]
for i in range(1, N+1):
    for j in range(V+1):
        if v[i] > j: # 不能将第i件物品装进去
            f[i][j] = f[i-1][j]
        else:
            # 不装 vs 装入该物品（前提：前 i-1 件物品中体积为 j-v[i] 的最优值加上 w[i]）
            f[i][j] = max(f[i-1][j], f[i-1][j-v[i]] + w[i])

             
# 𝑓[𝑖][𝑗] 表示“前 𝑖 件物品中，在总容量不超过 𝑗 的条件下，能获得的最大价值”
# 最终我们需要考虑所有 𝑁 件物品，并且总容量恰好为 𝑉，所以答案存储在 𝑓[𝑁][𝑉] 
print(f[N][V])  # 表示从 1 到 N 件物品中选，体积不超过 V 的最大价值




"""
    一维DP
用滚动数组保存而不是二维数组：
 滚动数组的本质还是减少空间复杂度，好比斐波拉契数列，递推式是f[n] = f[n - 1] + f[n - 2],我们只需要前两个数就可以递推下去数列，通过不断的覆盖，更新，本来需要额外开数组来存储的空间就省了下来，而dp问题是经典的以空间换时间，降低了空间复杂度其实也就是降低了时间复杂度
```

### 完全背包问题：acwing3

**完全背包问题的状态转移方程形式如下**：  

![image-20250306175051054](https://github.com/lllxQ000/tuchuangblog-img/blob/main/image-20250306175051054.png?raw=true)

**解释**：  
完全背包中物品可选无限次，因此状态转移需枚举所有可能的选取次数（理论上无限项）。通过观察可得递推关系：  
`
f[i,j] = max(f[i-1,j], f[i,j-v] + w)
`



**与多重背包的区别**：  

- 完全背包无次数限制，方程中的项无限延伸（用`...`表示）（无限次中直接就将`j - v`这个空间填满，而多重背包问题有次数限制，不一定能将`j - v`的空间填满，故要把选满`s`次的情况加上），无需像多重背包那样因选满`s`次而引入`j-(s+1)v`的额外项。  
- 多重背包因次数限制需显式枚举至`s`次，而完全背包通过递推优化避免了无限项的显式展开。

```py
"""朴素做法"""
```

### 多重背包问题：acwing5

![](https://github.com/lllxQ000/tuchuangblog-img/blob/main/bd6816affd9fd3fed55d8c61cc011498.png?raw=true)

- 为什么与完全背包问题的状态转移方程不同，多重背包问题是要在最后多一项？

 > [!IMPORTANT]
 >
 > 多重背包问题中，每个物品最多选s次。当计算`f[i][j-v]`时，需要从`j-v`的容量中选0到s次物品i。其中，选s次物品i需要占用`s*v`的容量，因此对应的状态为`j-v - s*v = j-(s+1)v`，此时总价值为`f[i-1][j-(s+1)v] + s*w`。这一项是**选满s次后的极限情况**，而完全背包没有次数限制，无需考虑这一项。因此，多重背包的`f[i][j-v]`中会多出`f[i-1][j-(s+1)v] + s*w`这一项。

##### 二进制优化（倍增思想）

> [!NOTE]
>
> - 讲一下为什么二进制优化可以哈。题目的意思是某物品最多有s件，我们需要从所有的物品中选择若干件，使这个背包的价值最大。题目并没有说某物品一定需要选多少件出来，也没有说一共要选多少件出来。只是选择若干件，至于选几件，无所谓，但要保证价值最大。按照优化的策略某物品有s件，我们给其打包分成了好几个大的物品。第一个大物品是包含原来该物品的1件，第二个大物品是包含原来该物品的2件，第三个大物品是包含原来该物品的4件，第四个大物品是包含原来该物品的8件,.....依次类推。此时我们就把所有的物品都重新进行了一个分类。原先每个物品最多s件，我们就把这个件数条件给消去了。取而代之的是，按照一定原先件数组合出来的新若干大物品。我们又已知按照我们划分成大物品进行搭配组合，一定能转化为原先的若干件小物品出来。并且选择某物品的最多件数，是不会超过原先该物品的s件。所以就转化为从下面这些若干件大物品中，选择能使背包容积最大大的情况下，价值最高。这个就是一个01问题。

- 这个题再原有的多重背包问题上进行了二进制优化
- 方法是：对每一组的vi, wi, si进行了再背包化，比如(1, 1, 3)被拆成了(1，1),(2，2)-(vi, wi)的两件物品，从而si越大所需要遍历的次数就越小log2(si)，但是V和W也在以2的倍数增长，所以这种优化对于一次性开辟大量地址的静态语言更快，其实动态语言应该也一样

```py
from sys import stdin

def bin(n):
    cnt = 0
    for i in range(1, n + 1):
        k = 1
        vi, wi, si = map(int, stdin.readline().split())
        while k <= si:
            cnt += 1
            v[cnt] = vi * k
            w[cnt] = wi * k
            si -= k
            k *= 2

        if si > 0:
            cnt += 1
            v[cnt] = vi * si 
            w[cnt] = wi * si
    return cnt

def dp(n):
    for i in range(1, n + 1):
        for j in range(m, v[i] - 1, -1):
            f[j] = max(f[j], f[j - v[i]] + w[i])
    return f[m]
```

### 最长上升子序列2（贪心 + 二分）：acwing896

#### **算法1(贪心 + 暴力枚举)** 𝑂(𝑛^2^)

![image-20250329122943965](https://github.com/lllxQ000/tuchuangblog-img/blob/main/image-20250329122943965.png?raw=true)

- 贪心思路：较小的数开头的数作为的子序列 比 较大的数作为开头的子序列 更好
- 贪心步骤：
  开一个数组`q[i]`，存的是以长度为`i`的上升子序列中末尾元素最小的数，
- `q[]`一开始是空集，长度为`0`
- 遍历每个数`x`，对于当前数`x`, 先找到一个最大的小于`x`的数`c`
  - 情况`1`：若找不到`c`, 扩大`q[]`的长度并记录当前数`x`
  - 情况`2`：若找到`c`, 就存在一个不等式`c < x ≤ a < b`, 则将`x`覆盖`a`的位置

**时间复杂度**

- 遍历每个数是 𝑂(𝑛)
- 遍历 q 数组每个数, 找到一个最大的小于当前数x的数c，最坏情况需要枚举所有数 𝑂(𝑛)
- 因此时间复杂度是 𝑂(𝑛^2^)
- 由于本题的`N = 100000, (10^5)^2 = 10^10` 会 `TLE`

于是有了算法2

#### **(贪心 + 二分)** 𝑂(𝑛𝑙𝑜𝑔𝑛)

- 基于`算法1`的单调性：**找到一个最大的小于等于当前数的数**, 我们可以用 **二分** 来优化
- 二分的思路：
  - 先定义边界，`l = 0, r = len`, 其中`len`是`q`数组的长度
  - 然后确定`check`函数, 可以先找到不等式中`c < x ≤ a ≤ b`的`c`
    - 通过`q[r + 1] = a[i]`来将`x`覆盖`a`的值
    - 同时也要考虑`算法1`的情况`1`, 需要扩大`q`数组的长度
      - 即`r + 1 > len`时, 表示**超出**了二分边界，这时就要`len ++`更新`q`的长度

**时间复杂度**

- 遍历每个数是 **𝑂(𝑛)**
- 遍历`q`数组每个数, 找到一个最大的小于当前数<mark>x</mark>的数<mark>c</mark> 𝑂(𝑙𝑜𝑔𝑛)
- 因此时间复杂度是 **O(nlogn)**

#### 2、状态压缩
我们知道状态压缩，顾名思义，<mark>就是需要考虑的状态非常多，我们如果用平常的思想去表示状态，那是非常不现实的，在时间和空间上都不允许，我们使用某种方法，以最小的代价表示某种状态。</mark> 那么，这通常是用进制来表示状态的，而选择几进制则根据要求使用的对象的点的状态有几种。一般来说，只有*0*和*1*，我们则是用二进制来表示，当然也有其他进制的题，在例题中会列举，需要我们灵活变通，主要谈二进制。

那么如何用二进制表示状态呢？我们发现，二进制上是按位分的，那么我们每一位可以看成一个点，而点上的取值则为该点的状态或者选择。例如 *00001001*这个状态则表示第一个点和第四个点状态为 *1*，其余的点状态为 *0* 。所以按照这种思想，我们能抽象的表示出一个很复杂的状态，实现了时间和空间的优化。

知道了这个，我们就按照正常动态规划的思想去写这类题目即可。

##### 3、使用场景
由上我们知道，状态压缩其实是有适用环境的：

- 1.状态需要有一定的状态单元。 即一个状态应该是保存一个集合，其中的元素值对应着*0* 或 *1* ，例如我们常见的棋盘，我们可以用 *0* 或 *1* 来表示棋子的放置状态。而整个集合即是一个 *01*串，即二进制数，我们通常用十进制表示。那么我们再进行状态转移或者判断的时候，需要先将十进制转化为二进制，再将二进制转化为十进制。

- 2.题目中限制的集合大小不会超过`20`。 这是最显著的特征，为什么呢？我们知道如果用二进制表示状态，那么集合大小为`20`的二进制状态有`2^20 - 1`，已经达到1*e*7的数量级了。

- 3.具有动态规划的特性。 对于动态规划，一般都是要求最优化某个值，具有最优子结构的性质。同时也需要满足状态转移的特性，而不是前一个状态毫无关系的。

1.状态转移的两个条件：

   - 状态`j`与状态`k`是否互斥
   - 横着的填完以后，`i-1`列的状态是否存在连续的偶数空格子

```py
def main():

        if not line:
            continue
        n, m = map(int, line.split())
        if n == 0 and m == 0:
            break
 
        M = 1 << n

        f = [[0]*M for _ in range(N)]

        #bool st[M];   存储每种状态是否有奇数个连续的0，如果奇数个0是无效状态，如果是偶数个零置为true。
        st = [False]*M

        # 二维数组记录合法的状态
        state = [[] for _ in range(M)]

        # 第一部分：预处理1	
        # 对于每种状态，先预处理每列不能有奇数个连续的0
        for i in range(1 << n):  # 即遍历n的所有二进制组合
            cnt = 0 # 记录连续的0的个数
            isValid = True #  某种状态没有奇数个连续的0则标记为true

            # 遍历这一列，从上到下
            for j in range(n):  
                if (i >> j) & 1:  # i >> j位运算，表示i（i在此处是一种状态）的二进制数的第j位； 
                    # &1为判断该位是否为1，如果为1进入if
                    if cnt & 1:
                    # 这一位为1，看前面连续的0的个数，如果是奇数（cnt &1为真）则该状态不合法
                        isValid = False
                        break
                        
                    
                    # 其实清不清零没有影响
                    cnt = 0   # 既然该位是1，并且前面不是奇数个0（经过上面的if判断），计数器清零。
                else:         # 否则的话该位还是0，则统计连续0的计数器++。
                    cnt += 1
            
            if cnt & 1:
                isValid = False   # 最下面的那一段判断一下连续的0的个数

            st[i] = isValid
            # 状态i是否有奇数个连续的0的情况,输入到数组st中

        # 第二部分：预处理2
        # 经过上面每种状态 连续0的判断，已经筛掉一些状态。
        # 下面来看进一步的判断：看第i-2列伸出来的和第i-1列伸出去的是否冲突
        for j in range(1 << n):   # 对于第i列的所有状态
            # 清空上次操作遗留的状态，防止影响本次状态。
            state[j].clear()

            for k in range(1 << n):   # 对于第i-1列所有状态

                # 解释一下st[j | k] 对应二进制位中至少有一个1时，结果为1 两位都是0时，结果为0
                # st[k|j]解释：第i-1列中1的总个数
                # 来源两部分：
                # st[k]表明第i-2列插入到i-1列的1的个数，i-1列被动生成的1
                # st[j]表明第i-1列插入到i列的1的个数，也就是i-1列自己生成的1
                    state[j].append(k)
                    # 二维数组state[j]表示第j行， 
                    # j表示 第i列"真正"可行的状态，
                    # 如果第i-1列的状态k和j不冲突则压入state数组中的第j行。
                    # "真正"可行是指：既没有前后两列伸进伸出的冲突；又没有连续奇数个0。

        f = [[0]*M for _ in range(N)]
        # 全部初始化为0，因为是连续读入，这里是一个清空操作。
        # 类似上面的state[j].clear()
        
        f[0][0] = 1   # 按定义这里是：前第-1列都摆好，且从-1列到第0列伸出来的状态为0的方案数。

        # 回到定义，f[0][x] 表示从-1列伸到0列（此处说的都是数组下标）状态为x的方案。
        # 我们发现，合法的方案只能是不伸过来，因为根本没有-1列。即x只能取0的时候方案合法，f[0][0] = 1;

        for i in range(1, m+1):   # 遍历每一列:第i列合法范围是(0~m-1列)
            for j in range(1 << n):   # 遍历当前列（第i列）所有状态j
                for k in state[j]:   # 遍历第i-1列的状态k，如果"真正"可行，就转移
                    f[i][j] += f[i-1][k]   # 当前列的方案数就等于之前的第i-1列所有状态k的累加。

        # f[m][0]表示 前m-1列都处理完，并且第m-1列没有伸出来的所有方案数。
        # 因为所有能横放且不冲突的地方已经使用了，要么就是填满了要么就是只剩下最后一列能让竖着填
```

#### 题目分析
**摆放方块的时候，先放横着的，再放竖着的**。总方案数等于只放横着的小方块的合法方案数。

> [!NOTE]
>
> - 如何判断，当前方案数是否合法？ 所有剩余位置能否填充满竖着的小方块。可以按列来看，每一列内部所有连续的空着的小方块需要是偶数个。
>
> - 这是一道动态规划的题目，并且是一道 状态压缩的dp：用一个N位的二进制数，每一位表示一个物品，0/1表示不同的状态。因此可以用<img src="https://assets.lllxq000.rest/image-20250307194620825.png" alt="image-20250307194620825" style="zoom:67%;" />中的所有数来枚举全部的状态:`range(1 << n)` <mark>[`n`的所有二进制组合为2ⁿ个，所以`range（1 << n）`其实就是将`i`定义为从0 ~ 2ⁿ - 1（不为2ⁿ因为2ⁿ的二进制长度为n + 1了）的长度为n的二进制组合，就是如当n = 3就是将`i`赋予二进制组合`000 ~ 111`,因为某列占不占有小方格是用0/1表示的，所以遍历长度为n的二进制组合就是在检查某列的小方格占用情况，而在该题的定义是上一列的1 x 2 的长方格伸到这一列的情况（伸过来了就是占了该列的格子，定为1，没有伸过来定为0）]</mark>



#### 状态表示
- 状态表示：`𝑓[𝑖][𝑗]` 表示已经将前 i -1 列摆好，且从第𝑖−1列，伸出到第 𝑖 列的状态是 𝑗 的所有方案。其中 𝑗 是一个二进制数，用来表示哪一行的小方块是横着放的，其位数和棋盘的行数一致。



#### 状态转移

> [!IMPORTANT]
>
> - 既然第 i 列固定了，我们需要看 **第i-2 列是怎么转移到到第 i-1列的**（看最后转移过来的状态）。假设此时对应的状态是 k（第 i - 2 列到第 i -1 列伸出来的二进制数，比如00100），k也是一个二进制数，1表示哪几行小方块是横着伸出来的，0表示哪几行不是横着伸出来的。
>
> - 它对应的方案数是 𝑓[𝑖−1,𝑘] ，即前 i - 2 列都已摆完，且从第 i - 2 列伸到第 i - 1 列的状态为 `k` 的所有方案数。



**这个`k`需要满足什么条件呢?**

> [!WARNING]
>
> 首先<mark>k不能和 j在同一行</mark>（如下图）：因为从i-1列到第i列是横着摆放的1 *2的方块，那么i-2列到i-1列就不能是横着摆放的，否则就是1*  3的方块了！这与题意矛盾。所以 k和j不能位于同一行。
>
> 既然不能同一行伸出来，那么对应的代码为<font color = red>`(k & j ) ==0`</font> ，表示两个数相与，如果有1位相同结果就不是`0`， <font color = red>`(k & j ) ==0`</font>表示 `k`和`j`没有1位相同， 即没有1行有冲突。
>
> 既然从第`i-1`列到第`i`列横着摆的，和第`i-2`列到第`i-1`列横着摆的都确定了，那么第`i-1`列 空着的格子就确定了，这些空着的格子将来用作竖着放。如果 某一列有这些空着的位置，<mark>那么该列所有连续的空着的位置长度必须是偶数</mark>。
>
> 自然想到的就是这两个操作共同的结果：两个状态或。 <font color = red>`j | k`</font> = 01000 | 10101 = 11101这个 <font color = red>`j|k`</font> （<mark>就是将<u>*i - 1*</u>列的`1`和<u>*i - 2*</u>列的`1`合并，这样子就知道了<u>*i - 1*</u>列有那几行横着摆了小方格了</mark>，并且<font color = red>`(k & j ) ==0`</font>保证了<u>*i - 1*</u>列和<u>*i - 2*</u>列的`1`没有冲突）
>
> 总共`m`列，我们假设列下标从<u>0</u>开始，即第0列，第1 列……，第m-1列。根据状态表示`f[i][j]`的定义，我们答案是什么呢？ 请读者返回定义处思考一下。答案是`f[m][0]`， 意思是 前`m-1`列全部摆好,且从第`m-1`列到 `m`列状态是`0`（意即从第`m-1`列到第`m`列没有伸出来的）的所有方案，即整个棋盘全部摆好的方案。

## 状态机

> **状态机模型和01背包问题的区别就在于，01背包中每个物品选或不选都是独立的， 不受前者约束不对后者产生影响，而状态机不一样。换成01那种状态之间的转化图来看的话,01背包中0和1的转化不受任何约束，可以说是有向完全图；但是状态机不一样，由于某些条件下的边不存在，于是我们在 计算本次状态之前就可能需要了解前一次的状态，于是需要状态细分标记**



状态机重点在于当前位置的每个状态都必须记录计算出来表示，不能`化零为整`，每一个状态都必须单独结算，并且当前位每个状态都有可能是上一位的每个状态转移而来，所以当前位的每个状态都需要计算比对一遍上一位的每个状态加上当前`动作`所造成的状态。比较抽象的概念，建议细看最后一个状态机问题：`acwing5408：保险箱`



### **1. 对比总结**

| **维度**     | **普通DP（单一维度状态）**             | **状态机模型（多维度状态）**               |
| :----------- | :------------------------------------- | :----------------------------------------- |
| **状态含义** | 记录某一直接属性的结果（如位置、容量） | 区分系统当前所处的操作模式（如持有、进位） |
| **设计目标** | 简化问题，聚焦单一属性递推             | 管理多模式切换对后续操作的影响             |
| **转移规则** | 直接递推，无分支条件                   | 多分支条件，确保模式间合法转移             |
| **典型问题** | 斐波那契数列、编辑距离                 | 股票买卖、保险箱进位/借位                  |

------

### **2. 通俗类比**

#### **普通DP：单一维度的“流水线”**

- **类比**：工厂流水线上记录每个工位的完成进度。
  - 每个工位（状态）只需关注自己的任务（如组装零件数量）。
  - 无需关心其他工位的操作模式（如是否使用特殊工具）。

#### **状态机模型：多模式的“交通信号灯”**

- **类比**：交通信号灯需要区分红灯、黄灯、绿灯三种模式。
  - 每种模式（状态）对应不同的通行规则（如红灯停、绿灯行）。
  - 切换模式时需遵循严格条件（如黄灯过渡到红灯）。

------

### **3. 如何选择状态表示？**

1. **普通DP适用场景**：
   - 问题无需跟踪系统行为模式。
   - 状态仅需记录直接属性（如位置、数量）。
   - **示例**：计算斐波那契数列、最长公共子序列。
2. **状态机模型适用场景**：
   - 问题中存在多模式切换（如持有股票、进位/借位）。
   - 后续操作依赖前序状态的行为模式。
   - **示例**：股票买卖含冷冻期、正则表达式匹配。

### acwing5408: 保险箱

<img src="https://github.com/lllxQ000/tuchuangblog-img/blob/main/image-20250403113825152.png?raw=true" alt="image-20250403113825152" style="zoom: 50%;" />

用`𝑓[𝑖][0]`、`𝑓[𝑖][1]`和`𝑓[𝑖][2]`表示当前位不进不退、当前位通过加法发生进位和当前位通过减法发生退位需要操作的最少次数。为了达成该位只受上一位的状态的影响，故此我们需要从右往左遍历（用`num_𝑥`表示文本串当前位的数字，用 `num_𝑦` 表示模板串当前位的数字）：

- 显而易见的不进不退时的操作次数 = `𝑎𝑏𝑠(num_x - num_y)`
- 而进位时的操作次数应为 `10 + (num_y - num_x)`
  - 即模板数减去文本数  如 2 -> 7  2进位成 17 就要 加上10 +（7 - 2），再如8 -> 3  8进位成 13 就要 加上10 + （8 - 3）且上一位有产生退位或者进位时，需要让 num_x <font color = blue>- 1/+ 1</font>
- 退位时应为 `10 + num_x - num_y`
  - 即文本数减去模板数  如 2 -> 7  2退位成 “- 7” 就要 减去10 +（2 - 7），再如8 -> 3  8退位成 “-3” 就要 减去10 + （3 - 8）且上一位有产生退位或者进位时，需要让 num_x <font color = blue>- 1/+ 1</font>
- 而最重要的初始化也要很清晰，初始的个位没有上一位的进位退位影响

1. 当前位没有发生进位`𝑓[𝑖+1][0]`(这里我从 i + 1 开始，规定 f[0] 是个位)： 
（1）上一位操作完了之后当前位没有发生改变，那么：
当前位不进位需要操作的次数即为：`step1 = 𝑓[𝑖][0]+𝑎𝑏𝑠(num_x - num_y)`。
（2）上一位操作完了之后当前位增大了一位，那么：
当前位不进位需要操作的次数即为：`step2 = 𝑓[𝑖][1]+𝑎𝑏𝑠(num_x - num_y + 1)`。
（3）上一位操作完了之后当前位减小了一位，那么：
当前位不进位需要操作的次数即为：`step3 = 𝑓[𝑖+1][2]+𝑎𝑏𝑠(num_x - num_y - 1)`。
综上：`f[i + 1][0] = min(step1, step2, step3)`。
2. 当前位的数通过加法进位`𝑓[𝑖+1][1]`：
（1）上一位操作完了之后当前位没有发生改变，那么：
当前位通过加法进位需要操作的次数即为：`step1 = f[i][0] + 10 + num_y - num_x`。
（2）上一位操作完了之后当前位增大了一位，那么：
当前位通过加法进位需要操作的次数即为：`step2 = f[i][1] + 10 + num_y - (num_x + 1)`。
（3）上一位操作完了之后当前位减小了一位，那么：
当前位通过加法进位需要操作的次数即为：` step3 = f[i][2] + 10 + num_y - (num_x - 1)`。
综上：` f[i + 1][1] = min(step1, step2, step3)`。
3. 当前位的数通过减法退位`𝑓[𝑖+1][2]`：
（1）上一位操作完了之后当前位没有发生改变，那么：
当前位通过减法退位需要操作的次数即为：`step1 = f[i][0] + 10 + num_x - num_y`。
（2）上一位操作完了之后当前位增大了一位，那么：
当前位通过减法退位需要操作的次数即为：`step2 = f[i][1] + 10 + (num_x + 1) - num_y `。
（3）上一位操作完了之后当前位减小了一位，那么：
当前位通过减法退位需要操作的次数即为：`step3 = f[i][2] + 10 + (num_x - 1) - num_y `。
综上：`f[i + 1][2] = min(step1, step2, step3)`。

最终答案即为`𝑚𝑖𝑛(f[n - 1][0], f[n - 1][1], f[n - 1][2])`。

```py
# 创建[[0, 0 , 0]] * (n + 1)就是相当于创建n+1个[0,0,0]的引用，多个列表共享同一个引用
# 此时f[1][0] = 999  会让列表变成 n+1 个[999,0,0]

    step1 = f[i][0] + abs(num_x - num_y)  # 上一位不进不退   
    step2 = f[i][1] + abs(num_x - num_y + 1)  # 上一位进位
    step3 = f[i][2] + abs(num_x - num_y - 1)  # 上一位退位
    f[i + 1][0] = min(step1, step2, step3)
    
    # 第i位进位的状态
    step1 = f[i][0] + 10 + num_y - num_x  # 上一位不进不退   
    step2 = f[i][1] + 10 + num_y - (num_x + 1)  # 上一位进位
    step3 = f[i][2] + 10 + num_y - (num_x - 1)  # 上一位退位
    f[i + 1][1] = min(step1, step2, step3)
    
    # 第i位退位的状态
    step1 = f[i][0] + 10 + num_x - num_y  # 上一位不进不退   
    step2 = f[i][1] + 10 + (num_x + 1) - num_y   # 上一位进位
    step3 = f[i][2] + 10 + (num_x - 1) - num_y   # 上一位退位
    f[i + 1][2] = min(step1, step2, step3)
    
ans = min(f[n - 1][0], f[n - 1][1], f[n - 1][2])
print(ans)
```
