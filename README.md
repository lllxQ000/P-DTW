# DP思想
> **动态规划考虑“整体最优”，解决的是“局部最优不一定推出整体最优”的问题；而贪心只考虑“当前最优”，假设每一步的局部最优能够推出全局最优。**因为DP的状态转移公式需要使用上一层的所有状态（符合条件的状态）进行最优状态选择，那么要做好数据结构的边界处理，比如下面的P-DTW算法，建立二维矩阵存储累计距离，那么就需要处理好初始元素的“上一层”状态，故建立`[0,n] x [0,m]`矩阵而不是只建立`[0,n - 1] x [0,m - 1]`矩阵，边界值赋予无穷。但为什么只有 M[0,0]=0
>
> 因为它是 DP 的起点：还没有匹配任何查询元素，也没有匹配任何模板元素，累计代价为零

> ## 为什么必须取三个前驱的最小累计距离？
>
> 这是动态规划的核心。
>
> 假设我们要计算的当前局部距离是：
>
> ​                                                                                   `d(A_3,B_4)=0.1`
>
> 三个前驱状态已经算好的累计距离分别是：
>
> | 前驱状态 | 已有累计距离 | 当前点的局部距离 | 新的累计距离 |
> | -------- | ------------ | ---------------- | ------------ |
> | M[2, 4]  | 0.8          | 0.1              | 0.9          |
> | M[2, 3]  | 0.4          | 0.1              | 0.5          |
> | M[2, 2]  | 0.2          | 0.1              | 0.3          |
>
> 注意，三种方式到达当前点时，当前局部距离都是同一个值 0.1。变化的是到达这里之前，已经累计了多少代价。
>
> 因此：
>
> ​                                              `M[3,4] = 0.1 + min(0.8, 0.4, 0.2) = 0.1 + 0.2 = 0.3`
>
> 算法选择从 M[2, 2] 出发的路径，因为它此前的累计代价最小。
>

>
> 可以把 P-DTW 理解为：`把两段流量波形放在一起，不要求每个时间点严格对应，而是允许波形在时间轴上错位，通过动态规划寻找累计特征差异最小的匹配路径。`
>
> 上图就是这个思想的示意。下面结合两段流量波形，逐步对应到伪代码。
>
> ## 1. 两段波形分别代表什么？
>
> - 波形 A：在线捕获的视频流量特征，转换为一个查询序列。
>- 波形 B：本地指纹库中保存的视频流量特征，转换为一个模板序列。
> 
> 假设横轴是时间，纵轴是某种流量特征，例如单位时间内的数据包数量、流量大小，或者论文定义的其他特征。
> 
>即使是同一段视频，由于网络抖动、采样时间不同、播放速度变化，两条曲线也可能出现时间偏移。
> 
> 例如，A 的一个波峰出现在第 20 个采样点，B 的对应波峰可能出现在第 22 个采样点。
> 
> 如果强制逐点比较，就可能认为两段流量差异很大；P-DTW 则尝试通过调整匹配路径，判断它们的整体形状是否接近。
> 
> ## 2. 对应到伪代码，DP 矩阵在做什么？
> 
> 假设 A 有 n 个采样点，B 有 m 个采样点。
> 
> `M[i,j]=匹配到 A 的第 i 点和 B 的第 j 点时的最小累计代价`
>
> 每次计算：
>
> ![image-20261010194434270](https://pub-64ffffada5d441c18d41525eba7abb52.r2.dev/PicGo/image-20261010194434270.png)
>
>可以把它理解为：
> 
>1. 先计算当前两个采样点的特征差异 `d(Ai,Bj)`。
> 2. 查看上一行三个允许的前驱位置。
>3. 选择累计代价最低的前驱。
> 4. 加上当前点的特征差异，得到 `M[i, j]`。
>
> 这里的三个前驱，分别允许模板序列停留、前进一格或前进两格。它们并不代表三种不同的相似度，而是三种可能的匹配路径。
>
> ## 3. 为什么它可以识别时间错位的波形？
>
> 假设同一段视频的两次流量采样存在轻微时间偏移：
>
> - A 的波峰出现在位置 20。
>- B 的波峰出现在位置 22。
> - A 的波谷出现在位置 32。
>- B 的波谷出现在位置 35。
> 
>逐点比较时，波峰和波谷可能对不上；P-DTW 可以沿着不同的匹配路径，将 A 的波峰与 B 中稍后出现的波峰对应起来，再继续匹配后续特征。
> 
>如果两个波形的形状整体相似，这种时间调整就可能降低累计距离。
> 
>但是要注意，P-DTW 不是直接比较两条曲线的整体轮廓，而是通过离散采样点之间的距离和允许的步进方式，间接评估形状相似性。
> 
>## 4. 回到你之前指出的假匹配问题
> 
>这里正是算法设计中需要重点关注的地方。
> 
>假设 A 的特征序列为：
> 
>`A={1,2,3}`
> 
>B 的特征序列为：
> 
>`B={1,2,4,3}`
> 
>如果允许直接从 `M[2, 2]` 跳到 `M[3, 4]`，那么模板中的特征 `4` 就被跳过了，而且没有受到惩罚。因此，最终距离可能仍然为 0。
> 
>在视频流量识别中，这相当于算法忽略了一个可能有区分价值的流量特征。
> 
>如果不同视频经常出现这样的局部特征重合，就可能发生误识别。
> 
>所以，判断这套算法是否可靠，除了检查 DP 递推式，还需要确认：
> 
>- 是否限制了匹配路径的最大跳跃幅度；
> - 是否对跳过的特征施加惩罚；
>- 是否要求足够高的模板覆盖率；
> - 最终是否结合其他指纹特征进行二次判定。
>
> 最关键的结论：P-DTW 的优势是容忍时间错位，而它的风险是过度容忍跳跃。 对于视频流量指纹识别，好的设计应该既允许同一视频的流量波形发生合理的时间变形，又不能让不同视频仅凭几个相同的采样点就获得零距离。

## 🔍 本质对比

| 维度         | 动态规划（DP）                             | 贪心算法（Greedy）                   |
| ------------ | ------------------------------------------ | ------------------------------------ |
| **核心思想** | 记住历史、对未来做出最优选择               | 每一步都选当前最优，走一步看一步     |
| **最优原则** | 整体最优由多个子问题的**最优组合**构成     | **每一步的最优**直接通向最终最优     |
| **是否回退** | 需要**回退、状态转移**                     | 一旦选择，**不回退、不更改**         |
| **求解方式** | 通常是**递推或递归**（含记忆化）           | 通常是**迭代直接构造解**             |
| **适用问题** | 子问题重叠，**后一步依赖前一步的多种情况** | 问题满足“贪心选择性质”和“最优子结构” |
| **效率**     | 相对较慢（但可优化到 O(n²)、O(n)）         | 通常更快，常为 O(nlogn)、O(n)        |

## 🧠 举例对比

这次我们用一个 6 层数字三角形，比前面的例子多两层，并且把贪心和动态规划都完整演算一遍，最后给出伪代码。

重点不是单纯让贪心走一条“看起来不太好”的路径，而是要明确证明：贪心每一步都选了当前更小的子节点，但最终总代价仍然比 DP 的最优解大。

## 一、贪心算法：逐步走一遍

为了避免相同数字导致的选择歧义，我们使用下面这组经过修正的 6 层数据：

![image-20261010150622392](https://pub-64ffffada5d441c18d41525eba7abb52.r2.dev/PicGo/image-20261010150622392.png)

我们约定：如果两个子节点数值相同，就选左边的节点。

### 每一步的选择

| 层数    | 当前节点 | 左下、右下候选 | 选择 |
| ----- | ---- | ------- | -- |
| 第 1 层 | 1    | 2、3     | 2  |
| 第 2 层 | 2    | 4、9     | 4  |
| 第 3 层 | 4    | 9、10    | 9  |
| 第 4 层 | 9    | 9、10    | 9  |
| 第 5 层 | 9    | 9、10    | 9  |

最终贪心路径为：

​                                                                1→2→4→9→9→9

总路径代价：

​                                                             1 + 2 + 4 + 9 + 9 + 9=34

贪心每一步都严格选择了当前较小的子节点，但它被引导到了左侧的高代价区域。

### 贪心伪代码

假设三角形使用二维数组 `a[i][j]` 保存，第 `i` 行有 `i` 个元素，采用从 1 开始的下标。

```python
Greedy(a, n):
    j = 1
    sum = a[1][1]

    for i = 1 to n - 1:
        left = a[i+1][j]
        right = a[i+1][j+1]

        if left <= right:
            j = j
        else:
            j = j + 1

        sum = sum + a[i+1][j]

    return sum
```

这里 `j` 表示当前节点在本行的位置。若选择左下节点，列号不变；若选择右下节点，列号加 1。

时间复杂度为 O(n)，因为每一层只做一次局部选择。

## 三、动态规划：从底部反向计算

DP 不急着从顶部作决定，而是先计算每个位置从当前位置走到底部的最小路径和。

我们先写出最底层的 DP 值，再逐层向上计算。

​                                                              1 + 3 + 1 + 1 + 1 + 1 = 8

### DP 伪代码

```py
DP(a, n):
    for j = 1 to n:
        dp[n][j] = a[n][j]

    for i = n-1 downto 1:
        for j = 1 to i:
            dp[i][j] = a[i][j]
                      + min(dp[i+1][j],
                            dp[i+1][j+1])

    return dp[1][1]
```

时间复杂度为 O(n²)，因为三角形总共有 n(n+1)/2 个节点；空间复杂度为 O(n²)，如果只保留相邻两层的 DP 值，也可以将空间优化为 O(n)。

## 四、最终对比：两种算法到底差在哪里？

![image-20261010151139431](https://pub-64ffffada5d441c18d41525eba7abb52.r2.dev/PicGo/image-20261010151139431.png)

两者的路径和相差 26。贪心在第一步选择了数字更小的 2，却因此进入了后续代价很高的区域；DP 计算了每个子节点到底部的最小代价，发现从数字 3 出发的完整路径反而更便宜。

这里要建立的关键认识是：

* 贪心： 只比较下一步的局部数值，作出选择后不再反悔。

* 动态规划： 比较下一步对应的最优子问题结果，再决定当前节点的最优值。

这也是为什么做算法题时，不能仅仅因为每一步都能选最小值，就认定贪心一定正确。必须证明局部选择不会损害全局最优性；如果无法证明，就需要考虑 DP 等能够系统比较不同决策的算法。
